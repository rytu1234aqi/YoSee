# 有得看

有得看是一个本地内容聚合阅读器：浏览器客户端、SQLite 数据库和单进程后台抓取。

## 启动

在项目目录执行（Python 3.12+）：

```bash
uv sync --locked
./.venv/bin/python -m server.run
```

浏览器打开 `http://127.0.0.1:8765`。启动命令会依次升级数据库、加载
`configs/sources/` 中的配置，然后启动网页和自动抓取。首次运行时列表可能暂时为空，
抓取完成后页面会出现更新提示；点击提示或顶栏刷新按钮即可读取新内容。

默认数据库为 `data/gamedev.sqlite`，可通过 `DATABASE_URL` 指定其他 SQLite 文件。
`Ctrl+C` 关闭服务，也会取消正在进行的抓取。自动抓取只在服务运行期间生效；
重新启动时会根据数据库中的上次抓取时间继续安排。

```bash
# 只阅读本地内容，不启动自动抓取
./.venv/bin/python -m server.run --no-auto-fetch

# 自定义端口、检查周期或来源配置目录
./.venv/bin/python -m server.run --port 8766 --poll-seconds 30 --sources-dir configs/sources
```

## 阅读与更新

界面顶部有三种视图，默认进入「刷流」：

- **刷流**：居中的一栏大卡片，像刷短视频一样一条条往下看。刷过的自动沉到底部，
  卡片上可直接「收藏」或「划走」；划走只是标记已读并离开当前屏幕，数据还在本机。
- **收藏夹**：只看收藏过的文章，可按「喜欢 / 回头再看」细分，支持搜索、离线看全文，
  以及导出纯链接清单（`.txt`，每行标题加网址）。
- **资料库**：原来的三栏界面，左栏筛选、中栏列表、右栏全文，宽度仍可拖动调整。

点卡片标题会打开全文：刷流和收藏夹用全屏阅读浮层，资料库仍用右栏。视图选择记在本机，
刷新后保持。下面描述的三栏细节适用于「资料库」视图。

- 使用 All articles / Unread / Saved、来源和搜索组合筛选。
- 每页 50 篇，列表底部的 Load more 继续加载，直到显示已到末尾。
- 分页使用文章时间和 ID 游标，后台新增文章不会把已加载页面挤动。
- 三栏宽度可拖动中间的竖直分隔条调整；分隔条也支持左右方向键（按住 Shift 加速）、
  Home/End 或双击恢复默认。宽度保存在本机，刷新后保持。中等宽度窗口（561–1000px）
  仍保持三栏并排、只是默认列宽更小；只有 ≤560px 才切换为堆叠布局并隐藏分隔条。
  首页与静态资源一律返回 `Cache-Control: no-store`；此外首页会把 `web/` 下除首页模板
  外的静态文件内容指纹（sha256 前 12 位）注入 `app.css` / `app.js` 的 URL
  （`?v=<hash>`）。`app.js` 内部对 `feed-store.mjs` / `article.mjs` / `layout.mjs`
  的模块导入也由服务端加上同一个指纹：只用裸路径时，内嵌 WebView 可能连请求都不发就
  复用旧模块，缺少新导出的函数会让整段脚本静默失效，表现为列表空白、状态文字不更新、
  拖动条无反应。改写只发生在响应里，磁盘文件保持原样，所以指纹计算稳定。
  内嵌 WebView 可能在加上 `no-store` 之前就永久缓存了旧样式表，
  只有换成从未请求过的 URL 才会重新下载，否则新 HTML（含两条分隔条）会被旧的三列
  CSS 自动排版，把详情区挤到第二行。访问 `/?debug=1` 可在右下角显示视口宽度、
  实际网格列宽和三栏是否同排，并把同样的几何信息打到服务端访问日志
  （`GET /health?w=...&cols=...`），便于排查内嵌预览面板。
- 详情页支持已读/未读、保存/取消保存；修改立即反映在列表中，重启后保留。
- 顶栏刷新仅重新读取数据库。后台默认每 30 秒检查一次到期来源，实际抓取频率遵循
  每个 YAML 的 `fetch.interval_seconds`，不会每 30 秒请求所有网站。
- 一个来源失败不会阻断其他来源；连续失败会延长间隔，最多退避至一天
  （原本就超过一天的间隔保持不变）。左栏显示检查时间、抓取进度及失败来源数。
- 少数站点会把全部历史文章塞进一个 feed（例如 Hugging Face Blog 约 900 条）。
  这类来源可在 YAML 的 `fetch` 段设置 `max_items_per_run: 50`，每次只导入最新的
  前 N 条，避免首次抓取把多年的旧文章灌进列表；不设置则不限制。
- 更新提示不会自动替换正在阅读的文章。正文只展示允许的 HTML 元素，原站脚本不会执行。
- 顶栏下载按钮可将本地文章和阅读状态导出为 JSON，便于备份和迁移。
- 顶栏上传按钮可导入之前导出的 JSON；导入内容会进入离线来源，不会参与自动抓取。
- 顶栏备份按钮会保存来源配置、文章和阅读状态，适合完整迁移本地数据库。

立即手动抓取仍可使用：

```bash
./.venv/bin/python -m server.ingestion.cli fetch-all
```

调度器用于一个本地服务进程。手动抓取（添加来源、左栏刷新）与后台轮询共用同一把锁，
不会并发写入 SQLite；仍不要同时启动多个服务进程。当前没有账号或跨设备同步，
默认仅监听本机。

## 刷流与收藏夹

- **刷过的沉底**：一栏卡片流把「未读」排在「已读」前面，组内顺序不变，分页游标不会错位。
  标记已读或划走后，卡片立即移到列表末尾或离开当前屏幕。
- **卡片上直接操作**：每张卡片自带收藏、划走按钮；已收藏的卡片还能直接标「喜欢」或
  「回头再看」。这些状态写在 `reading_states.tag`（`like` / `later`），随完整备份一起保存。
- **来源「只要什么」**：来源设置（齿轮）和添加来源对话框里都有一栏关键词，用逗号分隔。
  留空表示什么都要；设了之后，只有标题、摘要或正文里出现任一关键词的文章才会收进来，
  只有标题、没有正文的条目也会被跳过。被过滤掉的条数计入该次抓取的 `skipped`，
  在抓取历史里能看到。关键词存在来源的 `config_json.keywords`，编辑后立即生效。
- **久未更新的来源**：`/sources` 会给出 `stale` 与 `days_since_update`。判定阈值取
  「至少 7 天」和「该来源抓取间隔的 2 倍」中较大的那个，所以月刊不会因为十天没更新
  就被误标；左栏会把这类来源标成「久未更新」。
- **导出收藏链接**：`GET /export/saved-links` 只返回标题、网址、来源、分类和时间，
  不含正文；收藏夹页的「导出链接清单」按钮会把它存成 txt 文件。
- **卡片配图**：新抓到的文章会尽量用订阅源给的封面图；以前存下来的老文章没有封面，
  就从当时存下的正文（或摘要）里找第一张图顶上。实在找不到图，卡片会按来源生成
  一块专属配色的封面，带来源首字母和名字，不同来源颜色不一样，不会是一片雷同的空白；
  图片加载失败时也会自动换成这块封面。
- **只有链接的卡片**：有些站点只发一条链接、不发正文。这类卡片带一个「↗ 只有链接」
  的小标记，点卡片会直接新开一页到原网站，不再先弹一张空窗；点过之后自动算「刷过」并沉底。
  有正文的卡片照旧在软件里弹窗读，收藏、划走、分类按钮都不受影响。
  `<p><a …>Comments</a></p>` 这类网页标签也不会再被当成文字印出来。

## 旧链接自动清理

服务默认每天检查一次旧链接，**启动后要等满 24 小时才第一次执行**，不会在刚打开软件时
动现有数据。清理只针对「已刷过（`is_read=true`）且未收藏（`saved=false`）」的文章，并且还有
三道保护：最近 200 条（按发布时间）永不删、发布时间为空的不删、30 天内的不删。
收藏的文章和没刷过的文章永远不会被删。删除正文时，外键级联会一并清掉对应的阅读状态。

左栏底部显示当前保留条数；`GET /cleanup/status` 查状态，`POST /cleanup/run` 手动跑一次。
清理失败只记日志，不影响阅读和抓取。

```bash
# 完全关掉自动清理，所有链接一直留着
./.venv/bin/python -m server.run --no-auto-cleanup
# 把保护范围调大（默认 200，允许 50–100000）
./.venv/bin/python -m server.run --cleanup-keep 500
```

自动备份（每天一份 JSON 清单）在清理之前启动，长期运行的服务总是先有当天的留底。
不过备份和数据库在同一块硬盘，重要数据仍建议另外复制到其他磁盘或网盘。

## 自动备份

服务启动时检查当天有没有备份过，没有就立刻补一份；之后每 24 小时再做一次。
备份是**普通 JSON 文件**，放在数据库同目录的 `backups/` 下（默认 `data/backups/`），
文件名形如 `daily-2026-11-08.json`，周日额外留一份 `weekly-2026-W45.json`。
只保留最近 7 份每日和 4 份每周，更旧的自动删除；只删自己按命名规则生成的文件。

清单里只有三样东西：

- `sources`：订阅来源的配置（地址、名称、抓取间隔）。
- `links`：全部文章的链接、标题、来源、发布时间，以及「已刷过 / 已收藏」标记。
- `saved_articles`：只有收藏的文章附带正文，防止原站删文后打不开。

抓取记录、失败次数、缓存校验值、未收藏文章的正文都不写入备份；它们是运行时临时信息，
丢了不影响阅读。备份通过数据库查询生成，因此包含刚写入、还没合并进主文件的内容，
不需要处理 WAL 文件。写文件时先用临时文件校验 JSON 可解析，再原子改名，不会留下半截文件。
左栏底部显示最近一次备份日期；备份失败只记日志并在界面提示，不会打断阅读或抓取。

备份是**留底，不是一键还原**：可以用顶栏的导入按钮把文章导回，订阅来源由
`configs/sources/` 下的 YAML 恢复，一键还原按钮尚未实现。备份与数据库在同一块硬盘，
能防误删和升级出错，防不了硬盘物理损坏；重要数据请另外复制到其他磁盘或网盘。
备份目录已被 `/data/` 排除，不会进入版本库。

```bash
# 关闭自动备份
./.venv/bin/python -m server.run --no-auto-backup
# 改到别的位置
./.venv/bin/python -m server.run --backup-dir /path/to/backups
```

也可以手动触发一次：向 `/backup/run` 发 POST（需携带首页注入的 `X-Local-Token`），
状态查询用 `GET /backup/status`。

## 安全模型

- 服务启动时生成随机 token 并注入首页，所有 API 请求需携带 `X-Local-Token`；
  Host 非回环且无 token 的请求被拒绝，用于阻断跨站调用与 DNS rebinding。
- 来源 URL 拒绝回环、私网、链路本地与保留地址；重定向逐跳重新校验，响应体上限 8 MB。
- 外站 HTML 在入库前按标签/属性白名单净化，接口输出再次净化；所有响应附带 CSP。
- 导入内容按字段与长度严格校验，导入的来源强制离线，不会重新开始抓取。
- 删除来源时在同一事务内清除文章、抓取记录与阅读状态。

## 验证

```bash
./.venv/bin/python -m pytest -q
./.venv/bin/python -m mypy server
./.venv/bin/ruff check server tests desktop/scripts
node --test tests/web/*.test.mjs
```

Python 测试使用临时数据库和模拟 HTTP，包括启动初始化、来源调度、失败隔离、关闭取消、
抓取期间的并发写入，以及有新文章插入时的分页一致性；`tests/test_hardening.py` 覆盖
SSRF、本地 token、HTML 净化、导入去重与级联删除；`tests/test_backup.py`、
`tests/test_cleanup.py`、`tests/test_keyword_filter.py` 和 `tests/test_stream_features.py`
分别覆盖每日备份、旧链接清理的保护规则、关键词过滤与刷流/收藏夹接口。
`tests/test_reader.py` 依赖可选的 Tkinter，环境没有安装时会自动跳过。
前端逻辑测试仅需要 Node.js，不需要 npm 依赖；`tests/web/stream.test.mjs` 覆盖沉底排序、
划走、分类筛选和三种视图的界面契约。
浏览器交互与外站当前可访问性需另行实测。

CI 在 `.github/workflows/ci.yml` 中执行同样四项检查，并额外校验版本一致性与
Android 源码拷贝是否与根目录同步。

## 主要入口

- `server/run.py`：初始化和启动命令。
- `server/ingestion/scheduler.py`：按来源间隔调度抓取，也是手动抓取的唯一入口。
- `server/security.py`：URL 白名单、HTML 净化与本地 Host 判定。
- `server/api.py`：`/feed/page`、文章详情和阅读状态、`/sync/status`，以及来源管理、
  发现、导入/导出/备份和本地请求守卫。
- `server/backup.py`：每日轻量 JSON 备份（链接流、收藏全文、订阅名单）。
- `server/cleanup.py`：旧链接自动清理及保护规则。
- `server/ingestion/keyword_filter.py`：来源关键词过滤，由 `pipeline.py` 在入库前调用。
- `web/feed-store.mjs`：分页状态、刷过沉底与收藏分类筛选的纯函数。
- `web/`：客户端界面、分页状态管理与正文渲染。

原有 `/feed?limit=50&offset=0` 接口保留兼容；客户端使用 `/feed/page` 返回的
`next_cursor` 请求后续页面。API 文档见本地 `/docs`。
